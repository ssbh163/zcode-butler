# 显示大小六案弧复盘——一夜六案,终局是"不要手动调整"

> **文档性质**:技术弧复盘(v2 认知层,写后冻结;只允许标注勘误,不改写结论)。

## 一、背景与结局

出发点:用户想在非 4K 屏把悬浮窗调大些。一夜之间经历六种方案(v0.6.33 三档 / v0.6.34 双滑块 / v0.6.35 五档幂指数 / v0.6.36 绝对倍率 / v0.6.37 等比×N / 回退 v0.6.33 三档),全部被否;终局是用户砍掉需求本身——"不需要手动调整面板大小了,uiScale=(屏宽/3840)^0.55 就行了"。两窗显示大小从此写死幂曲线(4K=1,2K≈0.80),无档位、无持久化、无 UI 入口。**最简方案不是第六案设计出来的,是前五案的成本换来的。**

## 三、分章叙事

### 3.1 三档时代 [10-05 | ca882bd/6748c00]

齿轮悬停弹「显示」弹框,三档切换(等比 / b^0.55 幂曲线 / 恒 4K),内存态不持久化。附带修掉了 kind 提取不匹配弹残留内容的 bug(弹框高度 472→333 为指纹)。**此案被替换的原因:用户要"更细的控制"——但这个"更细"后来被证明是伪需求。**

### 3.2 双滑块与自指反馈 [10-05 | fb567bf/f8b209c]

两窗各一滑块,widget-scale.json 持久化,stats 经文件轮询应用。**滑块实时预览当场翻车:调本窗大小的滑块本身随窗口缩放,鼠标与滑块相对位置每帧漂移=握不住(用户鼠标实测指认)**,改松手生效(input 只更新标签,change 才发消息)。这是本弧唯一一次纯工程问题(非语义问题)的返工。

### 3.3 语义三案拉锯 [10-05 | ca43f53/ce504d6/3562c6e/385af96]

0.45-0.65 这组同域数字,先后被实现为幂指数、绝对倍率(回退后又)等比增益——三案两返工。转折点在 v0.6.36 条目自记的教训:**数值语义歧义必须先摊开效果表(含"4K 拖动会怎样"一行)再实现**。v0.6.35 的"4K 恒 1 语义"在数学上是对的,在体验上是死的:4K 屏拖滑块零反应(1^x 恒 1)。

### 3.4 回退纪律 [10-05 深夜 | fb7c374/86a5249]

两次回退均高效:整块取历史终态提交逐字节核验(html 对 6748c00/ecd1de9 零差异),独立修复甄别保留(stats 的 v0.13m 屏 DPI 修复非弧线成员,不随回退),版本号按更新链单调惯例例外另升(同 763b430/3562c6e 先例,第三次验证有效)。

### 3.5 终局 [10-05 深夜 | 86a5249]

回退到 v0.6.33 三档数小时后,用户:"齿轮弹框不要了"。终态 = v0.6.32 的 html(弹框代码整族本就不存在)+ 定死 `s=(w/3840)^0.55`。**需求在"怎么调"迭代了六案之后,在"要不要调"上一步归零。**

## 五、决策复盘(否决模式归类)

1. **语义歧义类**(v0.6.35/36):同域数字两义,未先摊开效果表 → 两案返工。已提炼 AGENTS。
2. **方案天花板类**(全弧):六案都在"怎么调"上迭代;需求本身可撤时,正确的止损动作是向上问一层("要调到什么效果?"),不是换第七种调法。
3. **工程自指类**(v0.6.34):调 X 的控件受 X 影响 = 反馈回路,交互设计常识缺位。
4. **回退执行类**(✓ 正面):历史终态整取 + 逐字节核验 + 独立修复甄别 + 版本例外惯例,三次回退零事故,值得保持。

## 六、方法论沉淀

- **同域数字需求先摊开效果表**(含 4K/2K 各一行、拖动会怎样一行)再动手——本弧最大单点学费。
- **回退优先取历史提交整块恢复**(逐字节 diff 核验),优于按记忆重写。
- **回退时逐项甄别"弧线成员 vs 独立修复"**(v0.13m 教训:按提交归属撤,不按时间窗口撤)。
- 需求连续被否 ≥3 次时,把"要不要做这个需求"本身作为下一个问题抛出。
