# ZCode UI 插件协议调查(悬浮窗迁移决策依据)

> 2026-10-11 · 响应"ZCode 原生 UI 插件给了什么,悬浮窗能否迁成会话侧边面板" · 调查对象:本机桌面版 2.37.1(`D:\ZCode\resources\app.asar`,2026-10-10 构建,内嵌 CLI 2.6.1 = `resources\glm\zcode.cjs`)+ zai-org/ZCode main 分支 UI_PLUGIN.md(461 行中文指南,commit 662c30b 引入)+ zai-org/zcode-plugins `feat/ui-plugin` 分支(官方五示例)

> **一句话结论**:机制完整、本机已实装(无 flag 门控),迁移技术上随时可做;但**"随 ZCode 启动常驻"穷尽验证无任何通路**,用户拍板解耦——悬浮窗继续服役,等官方 auto-open/持久化落地后按 PROJECT.md §15 蓝图一次切换。同日已向官方提两个需求(见 §5)。

## 一、能力全貌(标注:本机代码确证 = asar/zcode.cjs grep 到实现;文档 = UI_PLUGIN.md 原文)

### 1. 清单声明(plugin.json `.zcode-plugin/plugin.json`)

```json
"mcpServers": {
  "butler": { "type": "stdio", "command": "node",
    "args": ["${ZCODE_PLUGIN_ROOT}/ui-plugin/dist/server.mjs"],
    "cwd": "${ZCODE_PROJECT_DIR}", "isolation": "workspace",
    "env": { "ZCODE_PLUGIN_ROOT": "${ZCODE_PLUGIN_ROOT}" } }
},
"ui": { "surfaces": [{
  "id": "butler", "title": { "zh-CN": "码管家", "en": "Butler" },
  "icon": "gauge", "server": "butler",
  "resourceUri": "ui://zcode-butler/panel.html", "availability": "session" }] }
```

- `server` 必须是本插件 mcpServers 键,自动命名空间化为 `plugin:<插件名>:<键>`(zcode.cjs 偏移 ~4,232,400,确证);校验失败仅 warning 不炸插件(~4,239,100 `parsePluginUiSurfaces`)
- **`availability` 是必填字面量 `"session"`**:严格相等比较,缺省或 `"workspace"/"global"` 直接丢 surface 带 warning(zcode.cjs ~4,240,100 `parseSurface` + RPC schema `z.literal("session")`,确证)——**枚举预留扩展位的直接证据**
- `icon` 文档未写但官方插件实证存在(lucide 名,如 disk-cleaner `"hard-drive"`)

### 2. 页面供给与沙箱

- 页面 = 插件自己 MCP server 返回的 `text/html;profile=mcp-app` 资源(整份 HTML 文本);官方做法 = 全部 JS/CSS 内联进单文件(disk-cleaner 的 esbuild 占位符替换法),HTML 上限 16MiB、单次读取 8MiB
- 渲染在自定义协议 `zcode-sandbox://` 独立 WebContents;**CSP 经 HTTP 响应头下发且 `script-src` 显式含 `'unsafe-inline'`**(asar ~283,164,400 `buildPluginSandboxCsp`,确证)——内联 `<script>` 无需 nonce 即执行,单文件形态无障碍
- `default-src 'none'`、`connect-src 'none'`(可经资源 `_meta["zcode/csp"]` 申报 connectDomains 放宽);无 Node/文件访问,一切数据经 server

### 3. 页面 API(`@modelcontextprotocol/ext-apps`,官方锁 2.0.0)

- `callServerTool`(继承 Agent 权限审批,`options.signal` 可取消)/ `readServerResource` / `listServerResources`;`registerTool`(模型反向调用页面工具);`sendMessage`(有用户手势直发否则确认)/ `updateModelContext`(下一轮注入)/ `createSamplingMessage`(应用内模型调用,**返回无 usage 无耗时**,确证)
- 遗留 `window.zcode` 别名层存在于插件沙箱(asar plugin-sandbox-alias.js `createOpenAiCompatApi`,确证),定位存量兼容;**单 App 不混用**、连接前先挂事件处理器、每活页面只建一个 App(官方诊断表明文)
- 工具 `_meta.ui`:`resourceUri`/`surface`/`visibility`(`["model","app"]` 或 `["app"]`)/`preferredDisplayMode`(inline/fullscreen;fullscreen 时 useEffect 自动开侧栏,asar ~326,929,165 确证)/`showInline`

### 4. server 生命周期(zcode.cjs 确证)

- **会话启动即全量拉起**所有已启用插件的 server(`startMcpStartup` → `connectConfiguredServers`,~13,099,300),非懒拉起;`resources/read` 不会补拉已死进程(`requireEntry` 抛 "MCP server is not leased by this session")
- isolation 默认 `session`(每会话一进程);**清单可逐 server 声明 `"workspace"` 跨会话共享单进程**(内置 node_repl 即此配置)——迁移蓝图采用 workspace,省进程且天然合流数据轮询
- 空闲回收:refs 归零后 30s 宽限杀进程(`Daa=3e4`);会话租约期内不回收

### 5. 数据推送链路(四段全通,确证)

页面 SDK `resources/subscribe` → 渲染层 host(IPC `mcp/uiSubscribeResource`)→ CLI 池化适配器(MCP `resources/subscribe`)→ 插件 server;回推:server 发 `notifications/resources/updated` → `routeMcpServerNotification` → v4Gateway op `pluginUi.resourceUpdated` → 页面回调,页面自行重读。**SDK 不自动重读,收到通知后必须自己 `readResource`**(官方诊断表第 6 坑)。

### 6. 关键限制

- 交互页面仅限桌面本地工作区;远程/SSH 只有普通工具记录(zcode-plugins issue #76 实证)
- 工具结果 `structuredContent` ≤64KiB / `content` ≤32KiB(butler-cache.json 实测 36.7KB 贴近前者上限 → 数据走资源通道 8MiB)
- stdout 只准协议消息、日志一律 stderr;`requestTeardown()` 只是记录非关闭;widgetState 内存快照不保证跨重启

## 二、面板打开语义(本次调查的核心判定,全部确证)

**打开通路唯二**:①用户从侧栏"添加标签"菜单点开(菜单项 = `plugins/listUiSurfaces` RPC 只读清单,`e3e`/`r3e`,asar ~327,106,700);②模型调用带 `_meta.ui` 的工具触发(inline 卡片,fullscreen 模式自动开侧栏,`pluginUiAutoOpenKeys` 每应用运行期每 key 只自动开一次)。

**穷尽否定清单**(2.37.1 上不存在,逐项 grep 实证):

| 假想通路 | 判定 | 证据 |
|---|---|---|
| 侧栏 tab 跨重启持久化 | ✗ | tab 列表纯渲染进程内存 Map(`PS`),localStorage 全量键清单无 sidePane 键,主进程零侧栏状态 |
| 会话冷启动自动恢复 | ✗ | 冷启动开新 draft(`startDraftInWorkspace`);`lastActiveTaskByWorkspace` 是 schema 僵尸键(22 处命中全是 zod 定义,零运行时读写) |
| 命令面板/快捷键/deep link | ✗ | Command Center 注册表全量无 plugin-ui 项;`zcode://` 仅 workspace/OAuth/share 三种 |
| autoOpen/defaultOpen 配置键 | ✗ | 桌面 settings 与 CLI config schema 均无;`--surface desktop` 只影响系统提示与 Gen UI 输出目录 |
| 外部进程触发 RPC 开 tab | ✗ | app-server stdio-only 无端口;`mcp/uiOpenInstance` 开的是 iframe 实例非 tab,且方向是 renderer→CLI |
| hook 驱动 UI | ✗ | hooks 无 UI 通道;SessionStart 只注入上下文,不驱动模型动作 → 首条用户消息前面板物理上无法出现 |

**佐证**:官方 UI 自己的"常驻"基线也只到 browser-use 标签(有磁盘 recovery store)——terminal 与 plugin-ui 标签重启都不恢复。

## 三、官方示例与坑

- 示例源码:`zai-org/zcode-plugins` **`feat/ui-plugin` 分支** `ui-plugins/`(不在独立仓库):excalidraw(文档型 SQLite)、openpencil、blender(真引擎桥)、showcase(53 项能力验收清单)、**disk-cleaner(面板+server 模板,迁移蓝图的直接参照:esbuild server + React 页面全内联 + 权限分层[只读 model+app/危险操作 app-only 且 `confirm:z.literal(true)`]+ 数据分层[模型一句话/面板 structuredContent])**;另有 zcode-mcp-app-dev(脚手架辅助插件)
- 官方诊断表七坑:面板不出现(作用域/清单键)、面板空白(MIME/dist 未拷)、**ext-apps not found(SDK 版本漂移:npm 已 2.0.3,官方锁 2.0.0 + MCP SDK 1.29.0,必须精确锁)**、图标不显示、数据不刷新(订阅 handler)、双 App/新旧 API 混用、**开发更新循环(同版本重装才刷新代码副本,正式分发必须升版本)**

- MCP Apps 是 extension 规范(apps.extensions.modelcontextprotocol.io),宿主支持名单含 ChatGPT/Claude/VS Code——该技能可迁移

## 四、决策(用户拍板 2026-10-11)

**解耦**:悬浮窗 hook 驱动零交互常驻的 UX 是硬需求,2.37.1 无原生通路;迁移的收益(退役 OS 级寄生层维护、官方轨道、UI 上限)可以等,代价(启动后无面板+面板占侧栏宽度)是现付 → 悬浮窗继续服役,面板蓝图入 PROJECT.md §15 待命,**触发条件 = 官方落地 surface auto-open / tab 持久化 / availability 扩展**。

## 五、可证伪预测(决策后冻结,落地时逐条打分)

1. `availability` 枚举将在后续版本扩展出 `"workspace"` 或等价的跨会话/auto-open 值(依据:字面量校验 + surfaces 设计意图)
2. 侧栏 tab 持久化将以 localStorage 或 settings 形式出现(浏览器 tab 已有 recovery store 先例)
3. 官方需求 Issue A(auto-open/持久化)与 Issue B(会话遥测暴露)至少一个在 1-2 个大版本内有回应;链接:〔提交后补〕
4. 若上游始终不加 auto-open,悬浮窗将长期双轨服役——此为该决策的已知残留风险
