# SetWindowRgn 与 DComp 兼容性实测(消化外部文档质疑)

> 触发:2026-10-05 v0.6.24 Rgn 上线次日,用户提供一份外部技术文档(典型 AI 生成科普风格),断言"SetWindowRgn 会主动禁用 DWM 硬件加速、与 DirectComposition 根本冲突,现代窗口应彻底弃用"。本文逐条实证后吸收——**属于"决策后对质"型知识地图**(决策本身见开发日志 2026-10-05 v0.6.24 条,此处沉淀实证依据与可证伪预测)。

## 1. 问题域形态学

Windows 窗口裁剪的两套机制分属两个时代:

- **GDI 时代(SetWindowRgn)**:区域作用于窗口的重定向表面(redirection surface)与 GDI 重绘路径。对**传统窗口**(有重定向位图、内容走 GDI/重定向合成),SetWindowRgn 确实会让 DWM 走特殊路径——外部文档说的"禁用硬件加速、回退软件渲染"是这个场景的真实历史行为。
- **DComp 时代(WS_EX_NOREDIRECTIONBITMAP)**:该扩展样式**移除窗口的重定向位图**,内容全程经 DComp visual 树(SwapChain)GPU 合成。此类窗口**没有可供降级的 GDI 表面**;SetWindowRgn 在这里退化为 DWM 合成输出的一个裁剪矩形(GPU 路径),不存在"回退软件渲染"的对象。

关键区分:外部文档把两个时代的结论混排成一张对比表,对"传统窗口 + 异形 Rgn"的警告全部成立,**对"NOREDIRECTIONBITMAP + DComp + 矩形带 Rgn"的组合不成立**——而 butler 悬浮窗恰是后者。

## 2. 外部文档论点逐条实证(架构 = 我们的生产实况)

| 外部论点 | 实证结果 | 证据 |
|---|---|---|
| 强制禁用 DWM 硬件加速,回退软件渲染 | **未发生** | Rgn 上线后(v0.6.24-28)粒子动画/过渡/掩码上报正常;6 秒 CPU 采样:宿主 powershell 2.34% + WebView2 渲染器 0.52%(浅色态粒子关闭;深色开粒子约 3%,与无 Rgn 时代 v0.6.15 重做后的基线一致) |
| 无抗锯齿,边缘硬裁剪 | **不可见** | 我们裁的是实体包络矩形带,四边离可见形状有 14px 出血,全部落在透明区;可见形状(胶囊轮廓)的 AA 由页面在 DComp 渲染内完成("渲染与命中分离"——tag 线注释原话)。只有用 Rgn 贴形状边缘裁异形才会见锯齿,从未这么用 |
| 复杂区域开销大 | **不适用** | 单个 `CreateRectRgn` 矩形 + 去重(包络不变不重设),是 Rgn 开销的最小形态;非多边形布尔组合 |
| 与 DComp 根本冲突,不能混用 | **不成立** | 同上,生产环境两者叠加运行两晚零异常 |

值得记录:该外部文档最后的方案选择表格,把"事件需要穿透到其他进程的窗口"的底层手段恰恰指向了 **SetWindowRgn**——与我们的实战结论殊途同归(跨进程穿透正是 HTTRANSPARENT 掩码的死角,见踩坑区 2026-10-05 条)。

## 3. 显式预测(可证伪)

1. **若未来 Windows 更新使 Rgn×NOREDIRECTIONBITMAP 组合出现渲染回退**,表象应为:渲染器/宿主 CPU 骤升(数量级,非几个百分点)+ 动画帧率肉眼掉。排查入口:对悬浮窗调 `ClearViewRgn()` 撤裁剪后对比 CPU 采样——若撤掉即恢复,坐实 Rgn 路径回退,需换向(双窗口:主窗恒小+弹框独立窗)。
2. **若我们未来把 Rgn 改成贴形状的异形区域**(非矩形带),外部文档警告的"边缘锯齿"立即生效——届时 AA 问题真实存在,不是伪问题。
3. Rgn 与 DComp 的合成顺序问题(如 DComp 动画期间 Rgn 变更的撕裂)在单矩形+redraw=false+去重下未观察到;若改用复杂区域或多 Rgn 并发,需重新验证。

## 4. 决策

维持 v0.6.24 方案(SetWindowRgn 实体包络 + NOREDIRECTIONBITMAP + DComp)。外部文档的四条警告均不落在我们的组合上;其唯一适用于我们场景的结论(跨进程穿透需 Rgn)已被实战采纳。
