# 素材文档格式模板(Chat2Doc 最终产物规范)

> 本文件是 Chat2Doc 产出的**素材文档**的格式说明与骨架。想调整产出结构,直接改本文件,
> 不动技能代码。素材文档 = 分批摘要后的结构化会话素材,**已是最终产物**(不做二次成文,
> 见 PROJECT.md D7)。读者:未来的你 / 接手的人,无需回看原始会话即可理解全貌。

---

## 文档骨架(组装最终文档时套用)

```markdown
# 会话素材:{一句话主题}

> 会话 {sess_id 短号} · {startedAt ~ endedAt 北京时间} · 模型 {model} · {N} 回合 / {M} 工具调用
> 由码管家 Chat2Doc 归档于 {归档时刻}

## 会话概览

{3-5 句话:这次会话做了什么、关键结论、留下的状态。由主代理在合并全部批次后写}

---

(以下为各批次合并后的对话回合素材,逐回合:)

# 对话回合#{n} {MM-DD HH:MM ~ MM-DD HH:MM}

## 用户
{用户输入全文(已过滤系统注入)}

## 助手
{助手正文全文(已过滤 thinking)}

## 工具调用
- **{工具名}**: {一句话摘要}
- **{工具名}**: {一句话摘要(相邻相似操作已合并,细节保留)}

***
```

## 工具摘要行写法(摘要子代理规则,从 session-doc-prompt 蓝图移植)

每个编号的工具调用写为一句话摘要,按工具类型:

- **Bash**: 一句话描述意图,不贴完整命令;只保留关键结果数字或结论。
  - ✅ `重新提取纯净源码。→ 386KB, 10642 行`
- **Edit**: 文件路径 + 一句话改了什么。
  - ✅ `app.js — 注入侧边栏菜单项(下载和工具之间)`
- **Write**: 文件路径 + 创建了什么。
- **Read**: 文件路径 + 功能性描述(从内容推断),不贴内容;多次读同文件可合并,但每个区域都保留功能性标签。
- **Grep/Glob**: 搜了什么 + 找到/没找到 + 关键发现。
- **Agent/Task**: 派了什么代理 / 收了什么结果,一句话。
- **TodoWrite**: 创建/更新了什么待办项。
- **WebFetch/WebSearch**: 看了什么链接/搜了什么 + 关键结论。
- **AskUserQuestion**: 问了什么 + 用户选了什么。
- **其他工具**: 一句话描述 + 关键结果。

连续相似操作合并:**减少行数,不减少信息量**——合并后每个操作仍保留在摘要中。

禁止:贴完整命令/完整输出/错误原文;以 `...` 结尾的截断内容(应摘要而不是截断)。
无关键信息的调用(如空输出探测)可省略该编号(merge 会删除占位行)。

## 输出格式(子代理 repl-N.txt)

每行一条:`编号→摘要` 或 `编号1,编号2,...→合并摘要`,不要输出其他任何内容。
示例:

```
5→检查 CSS 文件结构 → 单行,100638 bytes
0,1,2→收取 3 个并行子代理结果(路由分析、API 分析、UI 模式分析)
```

## 质量红线

- 不虚构:hints 里没有的信息不要编造,宁可不写
- 不丢关键转折:用户纠偏、方案变更、报错与修复,必须能在素材里读出脉络
- 时间均为北京时间;文件路径保持原文绝对路径
